安装之前

一定要有 CORSAIR Xeneon Edge 吗？

不需要。Xenon 最初是围绕那块屏幕设计的，但 Edge 只是它能运行的其中一块屏幕，而不是产品本身。多余的显示器、放在桌上的旧平板、触摸屏、主屏上的一个窗口，或者你口袋里的手机，效果都一样。如果你完全没有多余的屏幕，就用手机：在自家 Wi-Fi 下大约三十秒，而且你得到的是真正的仪表盘，不是遥控器。

真的免费吗？

是的。没有付费版，没有试用期，没有账号，没有广告，也没有为某个并不存在的档位留着不给的功能。许可是自定义的非商业许可：个人使用免费，你可以阅读、运行和修改源码。需要书面许可的是：出售它、把它放进商业产品、以自己的作品名义再分发，或把 Xenon 这个名字用在别的东西上。

如果你想表达感谢，有支持者档位：一个月 5，五个月 25，一年 50。它解锁目录里的额外主题和小组件、Discord 身份组，以及你在本站的名字。应用本身不会保留任何功能：这是一份谢意，不是许可证。

支持哪些系统？

Windows 10 和 11（64 位）、macOS 11 或更高（Apple Silicon 与 Intel 共用一个通用版下载）、以及 Linux（64 位）。

macOS 和 Linux 处于 Beta 阶段。 仪表盘、组件、商店和各种集成在三个平台上完全一致；仍有差别的是读取机器本身的那一层。平台对照表逐项写明了哪项功能在哪里可用。

需要 CORSAIR 的电脑或 iCUE 吗？

不需要。Xenon 在任何电脑上都能运行，不需要 CORSAIR 的硬件或软件。iCUE 只和两件可选的事有关：如果你更喜欢把仪表盘放在 iCUE 的 iFrame 组件里，以及控制 CORSAIR 的 RGB 设备。其余部分与它无关。

当 Windows 说它是病毒

简短版本

从 4.11.9 版起，Windows 安装程序已签名，Windows 会显示经过验证的发布者。但警告仍可能出现一段时间，因为 Microsoft 需要时间积累信誉，Defender 也会根据程序的行为作出判断。于是最多会有三个不同的系统给出三种不同的警告，处理办法也各不相同。它们都不是真的检测到恶意软件，你也不必只听我说：每个版本都会附带你可以自己核对的哈希值。

Windows Defender 报了 Xenon，现在它不见了

这是误报，也是大家写信给我最多的一件事。检测名通常以 !cl 结尾，意思是这个判断来自 Defender 的云端机器学习模型，而不是与已知恶意软件的特征匹配。对这个模型来说，每个新版本都是一个新文件，所以这个报警会随版本出现又消失。

把安装找回来：

  1. 打开 Windows 安全中心 → 病毒和威胁防护 → 保护历史记录，找到 Xenon 那一条，选择 操作 → 还原。
  2. 加一个排除项，避免再次发生：管理设置 → 排除项 → 添加排除项 → 文件夹，添加 %LOCALAPPDATA%\Xenon。
浏览器不让我下载，或者说发现了病毒

原因相同，拦你的角色不同：这是浏览器自己的信誉检查，Chrome 用 Google 安全浏览，Edge 用 SmartScreen。用 Ctrl+J 打开下载列表，在被取消的文件上选择保留或仍然保留。之后运行安装程序时如果 SmartScreen 再次提示，点击更多信息，再点仍要运行。

我怎么确认它安全，而不是只能选择相信你？

自己核对，也希望你真的去核对。每个版本都附带一个用项目密钥签名的 SHA256SUMS 文件。在 PowerShell 里：

Get-FileHash .\Xenon-Setup-x64.exe -Algorithm SHA256

把结果和该版本 SHA256SUMS 里 Xenon-Setup-x64.exe 那一行对比。如果一致，你手上的文件就与 GitHub Actions 在那个 tag 上从公开源码构建出来的完全逐字节相同，而那份源码的每一行都能在 GitHub 上读到。你也可以把它传到 VirusTotal：只有两三个引擎报警而其余都干净，这是信誉问题的样子，不是恶意软件的样子。

你也可以检查签名：右键点击文件，选择属性，打开数字签名选项卡，就能看到发布者的名称。4.11.9 及之后的版本都已签名，更早的版本没有，那些版本请用哈希核对。

只有对从官方 Releases 页面下载、并且核对过哈希的文件，才可以绕过警告。 劝人忽略警告正是真正的恶意软件会做的事，而哈希就是区分这两种情况的东西。

Xenon 根本打不开，而 Defender 什么都没说

在 Windows 11 上，这通常是智能应用控制，它和杀毒软件是两套系统。请查看 Windows 安全中心 → 应用和浏览器控制 → 智能应用控制。

它会拦下任何它尚未信任的应用，而且这个判断发生在杀毒软件介入之前。所以上面的排除项对它没有作用，也没有办法在保持开启的同时只放行一个应用。它只会在全新安装 Windows 11 时自动开启，因此它出现在刚重装过的电脑上，而不会出现在升级上来的电脑上。剩下两个选项：评估模式，由 Windows 观察你的使用方式并自行决定是否继续开启；以及关闭。

改之前请先知道：关闭智能应用控制是一条单行道。 除非重置或重装电脑，Windows 不会让你再把它打开。这是微软的设计，不是 Xenon 能绕开的。从 4.11.9 版起，Xenon 自己的文件都已签名，而微软表示，智能应用控制在自己无法判断时，会放行带有效签名的应用。所以请先在保持开启的情况下试试最新版本。如果它仍然拦截 Xenon，而你更想保持开启，诚实的答案是：那台电脑上没法运行 Xenon。

用着用着 Xenon 自己就关了

打开托盘菜单，选择 Open crash log。Xenon 每次启动和每次停止都会写一行，两种可能的原因就靠这些行来区分。

最后一行是 PANIC。 说明是应用自己出错退出的，那一行会写明是哪个线程、源码的哪一行出的问题。把它贴到 Discord 或一份缺陷报告里：有这一行通常很快就能修好。

最后一行是 launched，后面什么都没有。 那就不是应用自己决定停下的，而是外部把进程结束掉了；在 Windows 上几乎总是杀毒软件把正在运行的 xenon-native.exe 隔离了。到 Windows 安全中心 → 病毒和威胁防护 → 保护历史记录里找时间与窗口消失那一刻吻合的条目，先还原，再把 %LOCALAPPDATA%\Xenon 和 %LOCALAPPDATA%\Programs\Xenon 两个文件夹都加进排除项。Xenon 分布在这两个位置，只排除前一个，等于让整天运行的那一半继续暴露在同样的检测下。

Xenon 有签名吗？

有。Windows 版从 4.11.9 版（2026年9月20日）起已签名。安装程序、其中的应用和助手程序都带有 Authenticode 签名，所以 Windows 会显示经过验证的发布者，而不是“未知发布者”。

签名证明的是谁发布了这个文件，以及之后没有人改动过它。它不会从第一天起就带来信誉：SmartScreen 会随着下载的人越来越多逐渐给予信誉，Defender 也会根据程序的行为作出判断。所以一段时间内仍可能出现警告，而有一件事最有帮助。如果 Defender 报了你的下载，请到 microsoft.com/wdsi/filesubmission 提交误报，选择 Home customer，再选 Incorrectly detected as malware。两分钟就能填完，真实用户的反馈是有分量的，通常几天之内这个报警就会对所有人撤销。

macOS 版目前是测试版，还没有经过公证（notarize），这是 Apple 的另一道手续；首次启动的方法见下面关于 macOS 的问题。

macOS 和 Linux

macOS 说无法打开 Xenon，因为 Apple 无法验证它

目前是预期之内：这个应用没有经过公证（notarize），而公证需要付费的 Apple Developer 会员资格，这个项目没有。

在 macOS 15 及更高版本上，打开系统设置 → 隐私与安全性，滚动到底部，点击 Xenon 旁边的仍要打开。Apple 已经取消了以前右键的那种方式。在 macOS 11 到 14 上，右键点击应用，选打开，再点一次打开即可。两种方式都是每个版本只需一次。

在 macOS 上磁盘组件显示废纸篓是 0 B

废纸篓和 ~/Library/Caches 的大部分内容在完全磁盘访问权限之后，而 macOS 是按应用逐个授予这个权限的。没有它，这些文件夹看起来是空的而不是被拒绝，所以不会报任何错误，磁盘占用统计就悄悄少算了。

打开系统设置 → 隐私与安全性 → 完全磁盘访问权限，点 +，在“应用程序”里选择 Xenon，确认开关是打开的，然后退出 Xenon 再重新打开。

4.11.3 之前每次更新后都要重做，现在不用了。 macOS 把这个权限绑定在代码签名上，而过去的 Xenon 使用临时（ad-hoc）签名，每个版本看起来都像另一个应用，授权就悄无声息地失效了。现在 Xenon 使用自己的证书签名，各版本之间保持一致，所以权限能在更新后继续有效。不过升级到 4.11.3 这一次会最后重置一次，因为正是这个版本更换了身份。如果它在列表里却明显不起作用，用 − 移除 Xenon 再重新添加。现在 Xenon 会自己发现这种情况并在仪表板上告诉你。

macOS 上需要装什么？

唯一必需的是 Node.js，缺了 Xenon 会告诉你：brew install node。其余都是可选的，每一个只点亮一件事：

  • vladkens/tap/macmon：温度和 GPU 占用
  • switchaudio-osx：切换输出设备
  • ffmpeg：语音输入和语音回复

Xenon 会先说出你缺哪些，而不是之后才失败。

Linux 上怎么安装？

下载 AppImage（加上可执行权限后运行）或者 .deb。首次启动时它会在一个你能看见也能中断的终端窗口里提出安装仪表盘，并且在解压任何东西之前先用项目密钥验证下载。

安装包故意不替你做这件事：安装过程创建的一切都属于某一个用户账号，而软件包是以 root 身份、面向整台机器安装的。如果你根本不想用这个应用，可以从 Releases 下载源码 zip，运行 ./INSTALL.sh。

需要 nodejs npm unzip。可选项各对应一个功能：wireplumber（音量、麦克风、分应用混音）、wmctrl 和 x11-utils（应用切换器）、playerctl（即时的正在播放）、ffmpeg（语音）。运行 npm run doctor，它会告诉你缺了什么、每一项又会点亮什么。

对 macOS 和 Linux 来说，Beta 到底意味着什么？

仪表盘是同一个产品：一样的组件、一样的商店、一样的主题、一样的集成、一样能用手机访问。不同的是读取机器的那一层，所以有些传感器和系统操作还没有，或者行为不同。

关键在于：没有任何东西假装它在工作。在你的平台上没有数据来源的磁贴会用一句话说明，而不是永远转圈；平台无法执行的 Deck 按键会直接隐藏，而不是先给你、再失败。

安装、启动、更新

安装程序到底做了什么？

在 Windows 上，它安装应用，把仪表盘引擎装到 %LOCALAPPDATA%\Xenon 下，如果你没有 Node.js 就装上，并注册一个任务，让仪表盘在你登录时启动。它还会取回可选组件：用于温度的 FFmpeg、LibreHardwareMonitor 和 PawnIO，以及用于游戏内真实 FPS 的 PresentMon。

没有任何东西在暗中运行。 安装程序本身只负责装好应用并打开它；仪表盘那一半由应用随后提出，并在一个你可以看着、也可以中断的控制台窗口里执行。早先的版本是在后台悄悄做这件事的，而这恰恰是让未签名安装程序被隔离的典型形态，所以已经去掉了。

它会随电脑启动吗？可以关掉吗？

会，登录时就启动，所以你坐下时仪表盘已经在运行了。它跑在你自己的会话里而不是系统服务里，这是有意为之：会话之外没有音频设备列表、没有窗口列表、没有麦克风，也没有办法打开应用，一半功能会悄悄失效。

要卸载 Xenon，Windows 上运行 UNINSTALL.bat，macOS 上运行 UNINSTALL.command，Linux 上运行 ./UNINSTALL.sh。

怎么更新？

Xenon 会自己更新。有新版本时仪表盘会提示，点一下就会下载，在解压任何东西之前先验证签名，先装引擎再装应用，中途出问题会自动回退到上一个版本。你的设置、布局和笔记始终保留，旧版本残留的文件也会被清理。

怎么卸载？

Windows 上运行 UNINSTALL.bat，macOS 上运行 UNINSTALL.command，Linux 上运行 ./UNINSTALL.sh。三者都会先确认一次，然后彻底移除 Xenon：应用、开机启动项、本地服务、你的数据和安装文件夹。想保留设置、布局和笔记，请加上 --keep-data（Windows 上是 -KeepData）。删除数据文件夹会清除 Xenon 保存过的一切，包括用于让商店评分只计一次的那个随机 id。

为什么要管理员权限？

只在安装时要一次，为了两件事：配置 CPU 和硬盘温度读取（LibreHardwareMonitor 和 PawnIO，需要一个驱动级组件），以及注册开机启动任务。拒绝的话其他功能照常，只是没有温度。之后 Xenon 不会以管理员身份运行。

提示端口 3030 已被占用

几乎总是因为仪表盘已经在运行了，而这本来就是你想要的：打开 http://127.0.0.1:3030/ 就在那里。如果是电脑上别的程序占用了这个端口，可以在 server/server.js 里改。

使用 Xenon

真的可以把手机当屏幕用吗？

可以，而且它是你的仪表盘，不是遥控器：一样的布局、一样的组件、一样的主题，Deck 按键真的运行在电脑上。没有账号、没有云、不用装任何东西，在自家 Wi-Fi 下也没有任何数据离开家里的网络。大约三十秒就好。手机指南里写了两条路线，在家用的和在外面用的。

一定要用那个应用吗？

不用。应用只是包住仪表盘的一个窗口，而仪表盘本身是一个本地网页：在任何浏览器、任何显示器上打开 http://127.0.0.1:3030/ 就行。在触摸屏上应用值得装，因为它带来了游戏中也安全的触控和托盘图标。在 iCUE 里，一个指向同一地址的 iFrame 组件同样可用。

做法是在 iCUE 里添加一个网页（HTML）组件，把下面这段粘贴进去：<iframe src='http://127.0.0.1:3030/' width='100%' height='100%' frameborder='0'></iframe>

用 AI 需要 API 密钥吗？

只有想用云端服务商时才需要，而 Gemini 的密钥可以免费创建。Xenon 的其他功能不需要它也能用。

还有完全本地的选项：对话用 Ollama，语音用 Whisper，在设置里按需安装，任何东西都不会离开你的电脑。如果你选择了云端服务商，你的提示词会按该服务商的条款发送给它，而 Xenon 绝不会把内容发给你没有选择的模型。

看不到 CPU 温度

重新运行安装程序，并接受管理员提示，这样它才能安装 LibreHardwareMonitor 和 PawnIO 并注册需要权限的启动任务。有些笔记本和主板根本不提供传感器，这种情况下磁贴会直接说明，而不是编一个数字出来。

我可以自己做组件和主题吗？

可以，而且大部分都不需要写代码。主题、布局、氛围场景和 Deck 配置都在应用里做好，然后以一段任何人都能导入的代码分享出去。组件是运行在沙箱里的小型 HTML、CSS 和 JavaScript 包，读取传感器和执行操作的通道都有文档。

从创作者指南开始，目录里是别人已经做出来的东西。

它能控制 RGB 灯光吗？

可以：CORSAIR 设备通过 iCUE，另外 WLED、OpenRGB、Philips Hue 和 Nanoleaf 直接通过你的网络控制。它可以跟着温度或正在播放的音乐变化，也可以就停在你挑的一个颜色上。这是可选功能，在你配置之前一直是关闭的。

隐私与信任

Xenon 会把我的数据发到什么地方吗？

你的设置、笔记、任务、日程、Deck、搜索词和文件索引都留在你的电脑上。应用里没有分析 SDK，没有崩溃上报，也没有行为追踪。

但它也不是完全离线的，说成完全离线才是不诚实的版本：它会检查更新，也会在你打开天气或音乐 API 这类功能时联系对应的服务。隐私页面列出了应用可能发起的每一次请求、触发它的条件以及具体发送的内容，没有省略。

需要账号吗？

不需要。没有 Xenon 账号，没有登录，你和自己的仪表盘之间也没有我的服务器。像 Spotify 或 Twitch 这些你自己配置的集成，使用它们自己的凭据，在你设置之前一直处于休眠状态。

许可、费用与帮助

可以在公司用，或者放进我自己的产品里吗？

个人使用是免费的，包括你恰好用来工作的那台电脑。出售它、把它打包进商业产品、以自己的作品名义再分发，或者把 Xenon 这个名字用在别处，都需要事先获得书面许可。

如果你心里有具体的用法，可以来问：发邮件或者在 Discord 上说一声。答案常常是可以，附带一些条件。

去哪里求助？

Discord 最快，大部分问题实际上也是在那里被定位的。如果问题可以复现，一个写明系统、你做了什么、发生了什么的 GitHub issue 是最有用的。两边都是同一个人在看。

怎么支持这个项目？

如果你愿意，可以请我喝杯咖啡。支持者会得到 Discord 的身份组和 Hall of Supporters 里的一个位置。

支持满一年还多一样东西：我给你做一套主题。把调色板、照片、游戏，任何你希望仪表盘呈现的感觉发给我，我会把它做成一套 Xenon 主题，署上你的名字发布。每人每月可提一次需求。有一条排队的队列，我按顺序做，所以我不承诺日期，只承诺轮到你时一定做，并且第一版之后你有一轮修改。主题指的是配色、背景、强调色、字体，以及现有组件的排布。新组件和新功能是另一回事，不包含在内。

需求请发到 Discord 的 #theme-requests 频道：开一个帖子，写清楚你想要什么，把调色板或照片放进去。这个帖子就是你在队列里的位置，我也会在里面回复你。

不花钱的事同样有用：在 GitHub 上点个星、写一份有细节的 bug 报告、在目录里分享一个组件或主题，或者告诉某个有多余屏幕的人这东西存在。
