macOS 版 Xenonベータ

Xenon は、どの画面でも使える無料のウィジェットです。Mac 版はベータです。このページでは、今 Mac で動くもの、動かないもの、インストールと削除の方法を紹介します。

最終更新: 2026年11月8日

このページの内容

こんな方に ダウンロード 初回起動 動く機能 Xeneon Edge 権限 アンインストール

こんな方に

このページは、次のいずれかの画面でウィジェットを使いたい Mac ユーザー向けです:

  • デスクトップ。今ある画面にウィジェットを置けます。1画面で使う Xenonをご覧ください。
  • CORSAIR Xeneon Edge。 Xenon はもともと、この画面の 2560×720 の形に合わせて作られました。
  • 余っているモニター。 Xenon アプリは、選んだ画面で開きます。
  • タブレットやスマートフォン。 Wi-Fi を通じて端末のブラウザに同じダッシュボードを表示し、端末には何もインストールしません。スマートフォンとタブレットからのアクセスもベータです。スマートフォンやタブレットのペアリングをご覧ください。

ウィジェット、カタログ、テーマ、各種連携は Windows と同じです。違うのは Mac 自体を読み取って操作する部分で、下の表に1行ずつまとめています。

macOS 対応は ベータ です。ユニットテストはありますが、実際に使われた量は Windows 版よりずっと少ないです。

ダウンロードと動作環境

macOSベータXenon-macOS-universal.dmgmacOS 11 以降。Apple シリコンと Intel の両方に1つのファイルで対応します。
  • macOS 11 以降、Apple シリコンまたは Intel。.dmg はユニバーサルビルドなので、ダウンロードは両方で1つです。
  • Node.js 22 以降を推奨します。 Node.js 18 と 20 でも Xenon は動きますが、セキュリティ修正はもう提供されず、Xenon はログに警告を書き込みます。Node.js が入っておらず Homebrew がある場合は、セットアップが Homebrew でインストールします。Homebrew もない場合はそこで止まり、nodejs.org からインストールするよう案内します。

ほかは任意です。ツールごとに1つの機能が加わり、入っていないものはインストーラーが名前を挙げて知らせます:

  • brew install vladkens/tap/macmon: 温度と GPU 使用率。Xenon Helper が読み取れない場合だけ必要です。
  • brew install switchaudio-osx: 出力デバイスの切り替え。
  • brew install ffmpeg: 音声入力と読み上げ。

初回起動

Xenon を初めて開く

バージョン 5.0 から、Xenon は Apple Developer ID で署名され、Apple の公証を受けています。そのため macOS は開く前にアプリを確認できます。

  1. .dmg を開き、Xenon を アプリケーション にドラッグしてから開きます。
  2. インターネットからダウンロードしたアプリを開くかどうか、macOS が一度だけ確認します。開く をクリックします。

macOS が Xenon を確認できないと表示する場合、そのコピーは 5.0 より前のものです。このページから最新の .dmg をダウンロードして、そちらを開いてください。

4.11.13 までのバージョンは、プロジェクト独自の証明書で署名されており、公証は受けていませんでした。5.0 で署名が変わるため、アップデート後に macOS が、フルディスクアクセス、アクセシビリティ、画面収録など、すでに許可した権限をもう一度求めることがあります。システム設定 の プライバシーとセキュリティ で、もう一度許可してください。

ダッシュボードのエンジンのセットアップ

.dmg ではインストーラーを実行できないため、初回起動時に Xenon のウィンドウの中で、進行状況バーを表示しながら行います。Xenon は次のことをします。

  1. アプリに含まれているダッシュボードのエンジンを専用の Node.js ごとコピーします。何もダウンロードしません。
  2. <code>~/Library/Application Support/Xenon</code> にインストールします。
  3. ログイン項目を登録し、ログイン時に Xenon が開くようにします。
  4. エンジンを起動し、応答したらすぐにダッシュボードを表示します。

かかるのは 1 分ほどで、最初の一度だけです。途中で止まった場合は Xenon が理由を伝え、ファイルには触れずにもう一度試すを表示します。Mac のどのブラウザでも http://127.0.0.1:3030/ でダッシュボードを開けます。

ダッシュボードのエンジンは、Xenon アプリの子プロセスとして動きます。そのため、Xenon にフルディスクアクセスを1回許可すれば、エンジンにも適用されます。Node.js に許可すると Mac 上のほかのすべてのスクリプトがその許可を共有しますが、この方法ならそうなりません。

アップデートは Windows と同じ仕組みです。新しいバージョンを先にダウンロードして検証し、新しいバージョンが起動しなければ前のバージョンに戻します。

アプリのウィンドウを使いたくない場合は、リリースからソースコードの zip をダウンロードして展開し、INSTALL.command をダブルクリックします。ダッシュボードは同じですが、アプリがないと macOS が保護しているフォルダーには届きません。

Mac でできないことは、表示してから失敗させるのではなく、最初から隠します。動かない Deck キーはエディターに表示されず、データ源のないタイルはそのことを表示します。

Mac で使う Xeneon Edge

Xenon は初めて開いたとき、認識している画面を一覧にします。Edge を選ぶと、ダッシュボードがそこに移ります。あとから 設定 → ディスプレイ で変更できます。

タッチの動作は Windows と違います。macOS は USB タッチスクリーンに標準では対応していないため、Touchscreen Gestures のようなアプリが、タッチをマウスのクリックに、長押しを右クリックに変換します。Xenon は右クリックで Deck キーの「長押し」の操作を実行するので、この構成でも長押しが使えます。

Windows のみの機能が3つあります。Edge をタップしてもゲームのフォーカスを保つ、ゲームを邪魔しないタッチ。CORSAIR iCUE のライティング。そして仮想セカンドスクリーンです。

macOS の権限

ダッシュボードは、どの権限がなくても動きます。権限ごとに、特定の機能が使えるようになります。

  • フルディスクアクセス（Xenon に許可）。 検索とディスク容量ウィジェットが、ホームフォルダー、ゴミ箱、~/Library/Caches の大部分を見られるようになります。許可がない場合、Xenon はデスクトップ、書類、ダウンロードへのアクセスを1つずつ求めるのではなく、ホームフォルダーには立ち入りません。代わりに、正しい設定画面へのボタンが付いたお知らせを1つ表示します。
  • アクセシビリティ（Xenon Helper と Xenon に許可）。 Xenon Helper に許可すると、Deck キーから前面のアプリにキーボードショートカットを送れるようになります。許可するまで、その種類の Deck キーはエディターに表示されません。Xenon は起動時にこの権限を確認するので、許可したら Xenon を終了して開き直してください。Xenon に許可すると、手順の記録がクリックしたボタンの名前を書き留められます。許可がない場合、各手順は丸で囲んだ場所を示します。
  • 画面収録。 スクリーンショット、録画、インスタントリプレイ、AI の画面認識に必要です。許可がないと、デスクトップの壁紙しか写りません。
  • マイク。 音声入力、「Hey Bit」音声起動、録画に入れるあなたの声に必要です。許可がないと、Xenon はマイクを見つけられません。
  • カメラ。 録画の Web カメラバブルに必要です。応答するカメラがない場合、録画はカメラなしで続きます。
  • 入力監視。 手順の記録があなたのクリックを見られるようになり、Xenon が USB ドングル接続のマウスやキーボードのバッテリーを読み取れるようになります。手順の記録は、入力した内容は決して記録せず、入力したことだけを記録します。
  • オートメーション。 Xenon Helper がない場合だけ関係します。その場合、アプリスイッチャーはスクリプトによる方法に切り替わり、macOS がアプリケーションごとに一度確認します。

Xenon にフルディスクアクセスを許可するには:

  1. システム設定、プライバシーとセキュリティ、フルディスクアクセス の順に開きます。
  2. + をクリックし、アプリケーションから Xenon を選んで、スイッチがオンになっていることを確認します。
  3. Xenon を終了して、もう一度開きます。権限は起動時に読み込まれます。

バージョン 5.0 から、Xenon はリリースをまたいで変わらない Apple Developer ID で署名されているので、許可はアップデート後も残ります。5.0 へのアップデートのときだけは署名が変わるため、もう一度求められることがあります。Xenon が一覧にあるのに権限が明らかに効いていない場合は、マイナスボタンで削除してから追加し直してください。

アンインストール

  1. Finder で 移動、フォルダへ移動 を選び、~/Library/Application Support/Xenon と入力します。
  2. UNINSTALL.command をダブルクリックします。
  3. 削除するものをすべて一覧にして待機します。続けるには REMOVE と入力します。

アプリケーションフォルダーのアプリ、ログイン項目、ローカルサーバー、データ、インストールフォルダーを削除し、最後に自分のターミナルのウィンドウを閉じます。

設定、レイアウト、メモを残したい場合は、これが起動するスクリプト UNINSTALL.sh を、ターミナルから --keep-data を付けて実行します:

cd "$HOME/Library/Application Support/Xenon"
./UNINSTALL.sh --keep-data

代わりに --dry-run を付けると、一覧を表示するだけで何も変更しません。

Xenon をゴミ箱にドラッグしても、削除されるのはアプリだけです。ダッシュボードのエンジン、そのログイン項目、データは残ります。アンインストーラーはそれらも削除します。

質問

Xenon は Mac で動きますか？

はい、ベータとして macOS 11 以降で動きます。1つのユニバーサル .dmg が Apple シリコンと Intel の両方で動きます。ダッシュボード、ウィジェット、各種連携は Windows と同じで、一部のシステム機能は使えません。

Mac で Xeneon Edge を使えますか？

はい。Xenon は初めて開いたときにどの画面を使うか確認するので、Edge を選べます。macOS は USB タッチスクリーンに標準では対応していないため、タッチを使うにはタッチをクリックに変換するアプリが必要です。iCUE のライティングとゲームを邪魔しないタッチは Windows のみです。

macOS に Xenon を開けないと表示されるのはなぜですか？

4.11.13 までのバージョンは公証を受けていなかったため、macOS が確認できませんでした。5.0 から Xenon は Apple の公証を受けています。初回は、インターネットからダウンロードしたアプリを開くかどうかを macOS が確認するだけなので、「開く」をクリックします。それでも macOS が Xenon を確認できないと表示する場合、そのコピーは 5.0 より前のものなので、最新の .dmg をダウンロードしてください。

Mac で Xenon に必要な権限は何ですか？

ダッシュボードはどの権限がなくても動きます。フルディスクアクセスがあると、検索とディスク容量ウィジェットがホームフォルダーとゴミ箱を見られます。アクセシビリティがあると、Deck キーからキーボードショートカットを送れ、手順の記録がクリックしたボタンの名前を書き留められます。画面収録は、スクリーンショット、録画、インスタントリプレイ、AI の画面認識のためのものです。マイクは音声入力と録画に入れる声のため、カメラは録画の Web カメラバブルのためのものです。入力監視があると、手順の記録がクリックを見られ、Xenon が USB ドングル接続のマウスやキーボードのバッテリーを読み取れます。

Mac で Xenon をアンインストールするには？

~/Library/Application Support/Xenon にある UNINSTALL.command をダブルクリックし、求められたら REMOVE と入力します。アプリ、ログイン項目、ローカルサーバー、データ、インストールフォルダーが削除されます。

Mac 版 Xenon をダウンロード

Xenon-macOS-universal.dmg をダウンロードするか、ダウンロードページでほかのシステムを選んでください。先に見てみたい場合は、ブラウザでデモを開いてください。質問は Discord へどうぞ。
