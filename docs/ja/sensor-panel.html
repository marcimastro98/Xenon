セカンドスクリーン用の PC センサーパネル

Xenon は、PC の横に置く画面のための無料のダッシュボードです。システムのタイルは、CPU、GPU、メモリ、ディスク、ネットワークの値をリアルタイムのグラフで表示し、ゲーム内の実際のフレームレートも表示します。このページでは、各カードに何が表示されるか、Windows、Linux、macOS でそれぞれどこから値を読むか、何を追加でインストールする必要があるかを説明します。

最終更新: 2026年9月27日

システムのタイル

タイルのシステムの表示には8枚のカードがあります。4枚はマシンのカードで、残りの4枚は「ネットワーク & ゲーム」の下にあります。カードは隠したり、並べ替えたり、サイズを変えたりできます。CORSAIR Xeneon Edge の 2560×720 の画面では、低い高さをカードの間で分け合ってすべてが見えるようにし、縦に長い画面では空いたスペースを埋めます。

  • CPU。 使用率（%）、プロセッサーのモデル、そしてカードのヘッダーに温度を表示します。
  • GPU。 使用率（%）、またはタップ1回でビデオメモリの使用量を表示し、温度も表示します。ビデオメモリへの切り替えは、グラフィックカードがメモリを報告する場合だけ表示されます。
  • RAM。 使用率（%）、使用量と合計。Windows では、Windows が報告する場合、メモリの種類、速度、モジュールの構成、型番も表示します。
  • ディスク。 使用率（%）、空き容量、ドライブの名前、ファイルシステム、種類。ドライブが複数ある場合は、矢印で順に切り替えます。
  • Ping。 1.1.1.1 への3回の ping の平均（ミリ秒）。
  • レイテンシ。 ジッター、つまりその3回の ping のうち最も速いものと最も遅いものの差。
  • FPS。 プレイ中のゲームのフレームレート。詳しくは下で説明します。
  • ネットワーク。 現在のダウンロードとアップロードの速度。物理ネットワークアダプターの合計です。

ネットワーク以外のすべてのカードは直近40回の値を線で描くので、急な上昇が過ぎたあとでも見えます。ヘッダーには、PC が起動してからの時間が表示されます。

CPU、GPU、RAM、ディスクのカードは5秒ごとに更新されます。「設定 → パフォーマンス → センサーの更新間隔」で、2秒または1秒にできます。間隔を短くするほどハードウェアを読む回数が増えます。ゲームも動かしている PC でどれだけ負荷がかかるかは、設定に表示されます。

「ネットワーク & ゲーム」の4枚のカードは、システムの表示が画面に出ている間、3秒ごとに更新されます。

温度は「温度の単位」の設定に従って、°C か °F で表示されます。この設定は天気だけでなく、CPU と GPU のヘッダーと高温の警告にも反映されます。履歴のグラフは °C のままです。

ゲーム内の実際の FPS

Windows では、FPS のカードは PresentMon の値を読みます。PresentMon はセットアップが Xenon のフォルダーにダウンロードします。ゲームが Windows に渡すフレームをイベントトレースで数えるので、排他的フルスクリーンのゲームも計測できます。セットアップが求める管理者権限が必要です。

PresentMon がない場合、Xenon は Windows のデスクトップコンポジターの値を使いますが、これはウィンドウモードとボーダーレスのゲームでしか使えません。PresentMon がある場合、ゲームが動いていないときは数値の代わりに「なし」と表示されます。

フレーム生成がオンのときは、PresentMon が報告する範囲で、画面に実際に表示されるフレームをカードが追います。そのため、渡されたフレームの多いほうの数ではなく、ほかの FPS オーバーレイと同じ値になります。

Linux では、MangoHud で起動したゲームのフレームレートを MangoHud から取得します（Steam の起動オプションに mangohud %command%）。macOS にはフレームレートの取得元がないため、カードは空のままです。

Windows での温度

Windows では、センサーは小さな PowerShell スクリプト（cpu-temp.ps1、gpu.ps1、network.ps1）が読み取ります。これらは長く動き続ける1つのプロセス pwsh-worker.ps1 の中で実行されるので、数秒ごとに読み取っても、そのたびに新しいプロセスが起動することはありません。

値取得元必要なもの
CPU の温度、クロック、ワット数 取得元LibreHardwareMonitor 必要なものセットアップが PawnIO ドライバーと一緒にインストールします。管理者権限が必要です。
マザーボード、AIO、電源ユニットのファン 取得元LibreHardwareMonitor 必要なものセットアップが PawnIO ドライバーと一緒にインストールします。管理者権限が必要です。
NVIDIA GPU の使用率、温度、ビデオメモリ、ワット数、クロック 取得元nvidia-smi 必要なもの設定は不要です。PC にあれば Xenon が見つけます。
AMD と Intel の GPU の温度、ビデオメモリ、ワット数、クロック 取得元LibreHardwareMonitor 必要なものセットアップがインストールします。
グラフィックカードの各ファン（RPM） 取得元LibreHardwareMonitor 必要なものセットアップがインストールします。
nvidia-smi がない場合の GPU 使用率 取得元Windows のパフォーマンスカウンター 必要なもの不要です。
CPU 使用率、RAM、ディスク、ネットワーク、ping 取得元システム自体 必要なもの不要です。
ゲーム内の FPS 取得元PresentMon 必要なものセットアップがダウンロードします。管理者権限が必要です。

LibreHardwareMonitor と PawnIO は winget でインストールされるので、ファイルは Microsoft のパッケージマネージャーを通じて、それぞれの開発元から届きます。PawnIO は署名付きのドライバーです。Xenon が WinRing0 を同梱したことはありません。WinRing0 は、ハードウェア監視ツールに対するウイルス対策の警告の多くの原因になっている古いドライバーです。

ドライバーは管理者権限があるときだけ読み込まれます。セットアップ中に Windows の確認を拒否した場合、ファンとワット数の値は空のままで、CPU の温度が表示されないこともあります。その場合、ファンとエネルギーのウィジェットに センサーを有効にする ボタンが表示されます。Windows の確認1回で、Xenon のスタートアップタスクがそれ以降管理者権限で動くよう設定され、Xenon が再起動します。それでもセンサーが空のままなら、ウィジェットが PC の再起動を求めます。同じボタンは「設定 → パフォーマンス → ハードウェア センサー」にもあります。

LibreHardwareMonitor がない場合、Xenon は、マザーボードが提供していれば Windows が報告するサーマルゾーンの温度を使います。取得できない値は、作ったゼロを表示するのではなく、空欄のままにするか「--」と表示します。

Linux と macOS での温度

macOS 版と Linux 版の Xenon は ベータ です。ダッシュボードは Windows と同じです。違うのはマシンの読み取り方で、システムごとに専用の収集処理があり、同じ形で値を返すので、タイルは変わりません。

値LinuxmacOS
CPU の温度 Linuxカーネル自身のセンサー（AMD では k10temp、Intel では coretemp）。インストールは不要です。 macOSインストーラーが取得する Xenon Helper。管理者パスワードは不要です。予備の手段は macmon です。
GPU の使用率と温度 LinuxNVIDIA は nvidia-smi が必要です。AMD はカーネルから読み取ります。Intel の使用率は最も深いスリープ状態から出ている時間で計測し、Intel の温度はセンサーのあるチップでだけ表示されます。 macOSインストーラーが取得する Xenon Helper。管理者パスワードは不要です。予備の手段は macmon です。
ファンの回転数 Linuxカーネルが公開するすべてのファン。デスクトップのマザーボードの多くは、正しいモジュールを読み込むために lm_sensors が必要です。 macOS使えません。
CPU と GPU のワット数 Linux読み取りません。 macOS読み取りません。
ゲーム内の FPS LinuxMangoHud。MangoHud で起動したゲームが対象です。 macOS使えません。
ゲームモード Linuxx11-utils パッケージの xprop。sway と Hyprland では、それぞれの IPC。 macOSXenon Helper。

タイルが空のままなら、インストールフォルダーで npm run doctor を実行してください。Xenon と同じ方法でマシンを読み取り、動いているもの、ハードウェアがそもそも公開していないもの、壊れているものを表示します。コンピューター上の何も変更しません。

ファン、エネルギー、バッテリー、ディスク容量

+ パレットのシステムのグループには、システムのタイルだけでは足りないときのためのタイルが、あと4つあります。

ファン

PC が報告するすべてのファンの回転数です。Windows では、ファンは取り付け場所ごとにまとめられます。マザーボード、ハブまたは AIO、グラフィックカード、電源ユニットです。グラフィックカードの各ファンはそれぞれのタコメーターから読むので、ファンが止まる 0 RPM モードのカードでは、ファンが停止中と表示されます。NZXT Kraken や Aquacomputer Octo のような AIO クーラーやファンハブも読み取れます。

マザーボードが知っているのは「Fan #3」のような名前だけなので、名前をタップして変更できます。iCUE Link のような対応していないハブや、分岐ケーブルにつないだファンは回転数を報告できず、ウィジェットがそのことを表示します。ファンのウィジェットは Windows と Linux で動き、macOS では動きません。

エネルギー

CPU パッケージと GPU の現在の消費電力（ワット）です。CORSAIR HXi または RMi の電源ユニットを USB で接続している場合は、電源ユニットが測った PC 全体の消費電力も表示します。この数値は電源ユニットの出力で、コンセントでの値ではありません。

太陽光発電やスマートプラグのような Home Assistant の電力センサーを、PC の値の横に並べられます。PC の値は Windows のみです。

バッテリー

ペアリングした Bluetooth デバイス、ノート PC のバッテリーや USB 接続の UPS（充電中かどうかも表示します）の残量を表示します。「設定 → ライティング」の RGB ブリッジがオンの間は、iCUE 経由で CORSAIR のマウス、キーボード、ヘッドセットの残量も表示します。スリープに入ったデバイスは、古い数値のまま止まるのではなく、薄く表示されます。Windows のみ。

ディスク容量

ドライブを何が占めているかを、スキャンボタンではなくリアルタイムのファイルインデックスから表示します。タップして掘り下げるマップ、大きいファイル、バイト単位で検証した重複ファイル、そして一時ファイルやパッケージのキャッシュのように、安全に削除できるカテゴリーの決まった一覧です。それ以外のものはサイズが表示されるだけで、削除ボタンはありません。

クリーンアップはファイルをごみ箱に移すので、元に戻せます。唯一の例外はごみ箱そのものを空にする操作で、確定する前にそのことが表示されます。Windows と macOS では、インデックスはインストーラーが取得する Xenon Helper の中で動きます。Linux では Xenon 自身がインデックスを作ります。

センサー履歴と Guardian

「設定 → パフォーマンス」で センサー履歴 をオンにすると、システムのタイルに「履歴」のタブが加わります。CPU と GPU の温度と使用率、RAM の使用量を、直近の24時間、7日間、30日間のグラフで表示し、各グラフに最新の値とピークを示します。標準ではオフで、AI は必要ありません。

Xenon は5分ごとに1回値を記録します。1時間ごとの値を3日分、1日ごとの値を約3か月分、PC 上のファイルに保存します。24時間の表示は1時間ごとの値を、7日間と30日間の表示は1日ごとの値を使います。

同じタブには「PC 使用時間」も表示されます。期間中によく使ったアプリ、アクティブだった合計時間、そのうちゲームをしていた時間です。履歴がオンのときは、エネルギーのウィジェットにも CPU と GPU の消費電力の直近24時間のグラフが表示されます。

Guardian は同じ履歴を AI で使う機能で、「設定 → Xenon AI」にある任意の「高度なAI機能」の1つです。「PC の調子はどう？」と聞くと、履歴を分析します。Guardian がオンのときは、CPU が 90 °C、GPU が 88 °C、RAM が 95% に達するとお知らせも表示されます。それぞれ30分に1回までです。

ゲームモードとパフォーマンスモード

ゲームモードは標準でオンです。ゲームがフルスクリーンで動いている間、アニメーション背景と AI の光る演出が止まり、ダッシュボードがゲームと GPU を取り合わないようにします。ゲームを離れると元に戻ります。

判断にはフレームレートではなく、前面のウィンドウを見ます。タイトルバーのないフルスクリーンのウィンドウは対象になりますが、最大化したデスクトップアプリ、ダッシュボード自体、iCUE は対象になりません。Windows では追加のツールも管理者権限も必要ありません。

パフォーマンスモードは、「設定 → パフォーマンス」で自分でオンにします。「手動」では、システムのタイルの「最適化」か、設定の「今すぐ最適化」を押したときだけ動きます。「提案」では、ゲームや自分で選んだほかの作業が始まったときに最適化を提案します。「自動」では自分で最適化を適用し、作業が終わると元に戻しますが、アプリを閉じるときは必ずあなたの確認を待ちます。どの手順を行うかは自分で選べます:

  • ダッシュボードのアニメーションを一時停止する。
  • Windows の電源プランを高パフォーマンスに切り替える。
  • 前面のアプリの優先度を AboveNormal（通常以上）に上げる。
  • 選んだバックグラウンドのアプリを閉じる。強制終了ではなく終了を求め、Windows の重要なプロセスは常に対象外にする。

「元に戻す」を押すと、再起動したあとでも、以前の電源プラン、優先度、閉じたアプリが元に戻ります。電源プランと優先度の引き上げは Windows の機能です。

「ゲーム中は重いタイルを一時停止」のオプションは標準でオンで、ゲームの実行中や最適化が有効な間、ブラウザ、セカンドスクリーン、カメラのタイルのストリーミングも止めます。

質問

AIDA64 や HWiNFO は必要ですか？

いいえ。Xenon はセンサーを自分で読み取ります。Windows では LibreHardwareMonitor、nvidia-smi、PresentMon、Linux ではカーネル自身のセンサー、macOS では Xenon Helper を使います。LibreHardwareMonitor と PresentMon は、Windows のセットアップがインストールします。

CPU の温度が表示されないのはなぜですか？

Windows では、たいてい Xenon が管理者権限なしで動いていて、センサーのドライバーを読み込めないことが原因です。ファンかエネルギーのウィジェット、または「設定 → パフォーマンス → ハードウェア センサー」で センサーを有効にする を押し、Windows の確認を承認してください。LibreHardwareMonitor がまったくインストールされていない場合は、Xenon のフォルダーで INSTALL.bat をもう一度実行し、確認を承認してください。

Xeneon Edge にセンサーを表示できますか？

はい。システムのタイルはカードの間で高さを分け合うので、Edge の 2560×720 の画面にすべて収まります。同じダッシュボードは、どのモニターでも、タブレットでも、Wi-Fi でペアリングしたスマートフォンでも動きます。スマートフォンからのアクセスはベータです。

自分でセンサーパネルをデザインできますか？

はい。ベータのウィジェット SDK を使います。システムの値へのアクセスを承認すると、ウィジェットは使用率、温度、クロック、ファンの回転数、ワット数、FPS を読み取れます。システムのタイルが表示しない値も含まれます。始めるなら作成のページからです。

macOS と Linux でも動きますか？

はい。どちらもベータです。CPU と GPU の温度と GPU の使用率は両方で動きます。ファンの回転数と、MangoHud によるゲーム内の FPS は Linux では動きますが、macOS では動きません。CPU と GPU のワット数を読み取るのは Windows だけです。

Xenon をダウンロード

無料で、アカウントは不要です。Windows 版 Xenon をダウンロードするか、ダウンロードページで自分のシステムを選んでください。先に見てみたい場合は、ブラウザでデモを試してください。
