Claude Code on a second screen

Xenon's Claude Code tile shows your real 5-hour and 7-day quota, what each session is doing, and every permission request with Allow and Deny. It lives on the screen next to your PC: a Xeneon Edge, a monitor, a tablet or a paired phone.

Last updated: 27 September 2026

Add the tile from the + button, under System. Token counts work straight away. The real quota, exact session state and approvals need Claude Code to be connected, which you do from the tile itself. It runs on Windows, and on macOS and Linux, which are in beta.

The 5-hour and 7-day quota

Claude Code hands its status line the real limits of your subscription: the 5-hour window and the 7-day window, each with how much is used and when it resets. Once Claude Code is connected, Xenon reads those figures and draws them as two bars, each with a countdown to its reset.

The bars show what is used, the same way Claude's own usage page does. They turn amber at 70% and red at 90%.

The windows exist on Claude Pro and Max plans. An API key has none. On an API key, before you connect Claude Code, and after Xenon restarts until a session sends new figures, the tile shows a Weekly budget instead: a ceiling you pick (Pro, Max 5×, Max 20× or your own number) and this week's tokens measured against it.

Under the quota sit today's tokens, this week's, the cache hit rate and what the work recorded on this PC would have cost on the API. A taller tile adds the last 30 days and a split by project and by model. These numbers come from Claude Code's own session files in ~/.claude, read on your PC, so they work before you connect anything.

Live sessions and plans

With Claude Code connected, every Claude Code session on the PC gets a row: the project, the model, how full the context window is, and its state: working, waiting for you, or idle. Claude Code reports that state itself, so a row appears when a session starts, not a minute later.

A working session shows the command it is running and for how long. A waiting session says what it is waiting for. Sub-agents show as their own chips, and a conversation being compacted says so.

When Claude works through a checklist, the row shows that plan: how many steps are done, the step running now and the next ones.

Sessions you started before Xenon opened show up too. A session you close with Ctrl-C is marked as closed within a few seconds and leaves the list eight minutes later. A session that has gone quiet moves under Finished and stays there for an hour after its last activity, so you can still send it a follow-up.

The top bar has a small marker next to the clock: Clawd, Claude Code's pixel mascot. It walks while a session is working, blinks when one has finished and you have not looked yet, and hops when Claude is waiting for you. When it blinks, tap it to open the session that finished.

Approving permission requests

When Claude Code asks permission to run a command or change a file, the request appears on the tile with the tool and the exact command, and two buttons: Allow and Deny. Claude Code waits for your answer.

A request left unanswered for 25 seconds takes over the whole screen, so it does not sit unseen on another page. Commands with a wide reach, such as rm -rf or git reset --hard, take over the screen at once. When Claude asks to leave plan mode, the card shows the plan you are approving.

Nothing is approved for you. If you do not answer within nine minutes, if Xenon is closed or if the connection fails, the request goes back to the terminal, as it would without Xenon.

To answer from your phone, pair it with Xenon (beta). The phone shows the same dashboard, with the same Allow and Deny buttons. How to pair a phone.

If you would rather answer in the terminal, switch off Settings → Claude Code → Ask for permissions on this screen. Claude Code is then told straight away that this screen is not answering, and asks in the terminal.

Questions from Claude

When Claude asks you a multiple-choice question, the tile shows it with the options as buttons. Pick one, or several where the question allows it, and press Answer. Your choice reaches the session and Claude carries on.

The tile can only send options Claude itself offered. It cannot write an answer of its own.

In the terminal hands the question back to the terminal instead. The same happens after four minutes without an answer, and always when Answer questions on this screen is off in Settings → Claude Code. A question never takes over the whole screen.

Ask and Deck keys

Once Claude Code is connected, the Ask button on the tile starts Claude Code from the screen. Pick one of your projects, write what you want done, choose a model if you care to, and Claude Code starts in that folder. Progress and the answer come back to the tile, with a Stop button while it runs.

Tap a session to write it a follow-up. If it is still working, the message waits and goes into the same conversation when the current turn ends.

The Deck has two keys for it, in a Claude Code group that appears once Claude Code is connected. Ask Claude holds a project, a request and optionally a model, so one press starts that job. Stop Claude stops the newest run started from the dashboard that is still going.

Runs started from the tile or a key use Claude Code's normal permission mode, with no way to skip it, so anything your Claude Code settings do not already allow comes back as a card to approve. There is no key that approves a request. The project list is built from Claude Code's own history, so the dashboard can only start work in folders you already use.

Connecting Claude Code

  1. Add the Claude Code tile from the + button, under System.
  2. On the tile, press Connect Claude Code, then Connect.
  3. Restart any Claude Code session that was already open, so it starts reporting.

Connecting edits one file: your Claude Code settings.json, in ~/.claude or the folder CLAUDE_CONFIG_DIR points to. It adds a status line and a set of hooks. Each hook points at Xenon on 127.0.0.1, your own PC, and carries a key that Xenon created.

Before the first change, Xenon saves a copy of the file next to it as settings.json.xenon-backup.

Claude Code allows one status line. If you already had one, Xenon keeps it: its own script runs yours and prints what yours prints. If yours prints nothing within three seconds, Xenon's own short line appears instead.

Uninstalling Xenon takes out every entry it added, puts your own status line back and deletes the backup. Your own hooks are left alone. To do the same without uninstalling, run node server/claude-link.js unlink in the folder Xenon is installed in.

What is sent where

The tile uses no account and no API key. Its token counts come from files on your disk, and its live data comes from Claude Code on the same PC.

Claude Code's hooks and status line send their reports to 127.0.0.1, which is your own PC. Each report must carry a key that Xenon created, and Xenon refuses any report without it. The hooks send the key in a request header and the status line script reads it from Xenon's own data folder, so it never appears on a command line or in a process list.

Live session state is kept in memory. Xenon does not write it to disk, and it starts empty when Xenon restarts.

A paired phone can use the tile, answer requests and start runs, but it cannot send reports as if it were Claude Code: those addresses are refused to paired devices.

Xenon AI on your Claude or ChatGPT subscription

Separate from the tile, Xenon AI, the dashboard's assistant, can answer through your own subscription instead of an API key, since version 4.11.10. In Settings → Xenon AI, pick Claude Code or Codex. Xenon then asks the official program installed on your PC, signed in with your Claude or ChatGPT plan.

You sign in inside the program, through Anthropic's or OpenAI's own sign-in, and Xenon does not read, store or pass on your credentials. This is the only way Anthropic allows a Claude subscription to be used outside its own apps.

Settings shows whether the program is installed and signed in, and what to run if it is not. The model menu is filled by the program itself, so it lists what your account can use today.

The assistant keeps its dashboard tools: it can change the theme, set up Deck keys, add tasks and timers, and control lights and media. The program's own terminal and file tools stay switched off.

It is slower than an API key: a few seconds for a plain answer and around ten when it uses a tool, because the program starts for each answer. It draws on the same limits you code with. AI search, the disk advisor and Performance Mode's plan use it too, while the automatic one-liners from Bit, the dashboard's pet, never do.

Common questions

Can I see my Claude Code quota on a second screen?

Yes. Once Claude Code is connected, the tile shows the 5-hour and 7-day windows of a Claude Pro or Max plan, with how much is used and a countdown to each reset.

Can I approve Claude Code requests from my phone?

Yes, once the phone is paired with Xenon, which is in beta. The phone shows the same dashboard, and each request has Allow and Deny. See pairing a phone.

What happens if I do not answer a request?

Nothing is approved. After nine minutes, or if Xenon is closed, the request goes back to the Claude Code terminal as usual.

What does connecting change in my Claude Code settings?

It adds a status line and a set of hooks to settings.json, after saving a copy of the file. If you had a status line of your own, Xenon keeps running it. Uninstalling Xenon removes what it added.

Does the tile work with an API key?

Yes, without the quota windows, which only Pro and Max plans have. The tile measures your tokens against a weekly budget you set instead.
