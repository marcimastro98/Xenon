# Security policy

## Reporting a vulnerability

Please **do not open a public issue** for a security problem. A public report shows everyone how to attack people who have not updated yet.

Report it privately instead: open the [Security tab](https://github.com/marcimastro98/Xenon/security) and choose **Report a vulnerability**, or go straight to [the private report form](https://github.com/marcimastro98/Xenon/security/advisories/new). Only the maintainer sees it.

Helpful things to include:

* what an attacker can do, and what they need first (for example: the user opens a web page, a widget is installed, a device on the same network)
* the steps to reproduce it, and the Xenon version and operating system you tried it on
* the file or the request involved, if you know it

## What happens next

You will get an answer within a few days. Once the problem is confirmed, it is fixed in the next release, or in a dedicated one if it is serious. After the release, the advisory is published with credit to you, unless you prefer to stay anonymous.

## Supported versions

Security fixes go into the latest release. Xenon updates itself, so keeping it up to date is the best protection.

## What counts

Anything that lets a web page, a widget, a shared preset, a downloaded file, another device or someone else's content make Xenon do something the user did not ask for: run programs, read files or settings, reach the network on its behalf, or get past the permissions a widget was given.

A program already running on the same PC under the same user account is out of scope: it can already do everything the user can.
